# Practical 9: String Parsing using YACC-style Grammar

## Objective

Validate input strings using a recursive descent parser (equivalent to YACC) based on the following grammar:

```
S  → i E t S S' | a
S' → e S | ε
E  → b
```

---

## Grammar Explanation

| Non-Terminal | Production Rules          | Meaning                                      |
|-------------|---------------------------|----------------------------------------------|
| `S`         | `i E t S S'` or `a`       | An if-then block, or just `a`                |
| `S'`        | `e S` or `ε`              | Optional else clause (can be empty)          |
| `E`         | `b`                       | Boolean condition (only `b` is valid)        |

### Terminal Symbols
- `i` → "if"
- `t` → "then"
- `e` → "else"
- `b` → boolean expression
- `a` → statement/action

This grammar models the classic **dangling else** problem in language grammars.

---

## Implementation

### Language: C++

A **recursive descent parser** is used — a top-down parsing technique that directly mirrors the grammar rules, functionally equivalent to a YACC-generated parser.

Each non-terminal in the grammar maps to a C++ function:

| Grammar Rule | C++ Function    |
|-------------|-----------------|
| `S`         | `parseS()`      |
| `S'`        | `parseSPrime()` |
| `E`         | `parseE()`      |

### Parsing Strategy (LL(1))

The parser reads the input left-to-right with **one character of lookahead**:

```
parseS():
  if peek == 'i' → consume 'i', call parseE(), expect 't', call parseS(), call parseSPrime()
  if peek == 'a' → consume 'a', return true
  else           → return false (invalid)

parseSPrime():
  if peek == 'e' → consume 'e', call parseS()
  else           → return true (ε production, empty match)

parseE():
  if peek == 'b' → consume 'b', return true
  else           → return false (invalid)
```

After parsing, if the entire input is consumed → **"Valid string"**, else → **"Invalid string"**.

## All Test Cases

| Input       | Output         | Reason                                              |
|-------------|----------------|-----------------------------------------------------|
| `ibtai`     | Invalid string | After `ibta`, S'=ε but `i` is leftover — unconsumed |
| `ibtaea`    | Valid string   | `i b t a e a` → if(b) then a else a                |
| `a`         | Valid string   | Single statement — simplest valid string            |
| `ibtibta`   | Valid string   | `i b t (i b t a)` → nested if-then                 |
| `ibtaeibta` | Valid string   | `i b t a e (i b t a)` → if-then-else(if-then)      |
| `ibti`      | Invalid string | Inner S starts with `i` but no `b`, `t`, `S` follow|
| `ibtaa`     | Invalid string | After `ibta`, S'=ε but `a` is leftover             |
| `iea`       | Invalid string | After `i`, E expects `b` but got `e`               |
| `ibtb`      | Invalid string | After `ibt`, S expects `i` or `a` but got `b`      |
| `ibtibt`    | Invalid string | Inner S=`ibt` is incomplete — needs a final S       |

## Code Walkthrough

```cpp
// E -> b
bool parseE() {
    if (peek() == 'b') { consume(); return true; }
    return false;
}

// S' -> e S | ε
bool parseSPrime() {
    if (peek() == 'e') { consume(); return parseS(); }
    return true;  // ε — always succeeds silently
}

// S -> i E t S S' | a
bool parseS() {
    if (peek() == 'i') {
        consume();                         // eat 'i'
        if (!parseE()) return false;       // must have 'b'
        if (peek() != 't') return false;   // must have 't'
        consume();                         // eat 't'
        if (!parseS()) return false;       // must have another S
        return parseSPrime();              // optional else
    } else if (peek() == 'a') {
        consume(); return true;
    }
    return false;
}
```

---

## Key Concepts

- **LL(1) Grammar**: Parsed left-to-right with 1-token lookahead, no backtracking needed.
- **ε (epsilon) production**: `S' → ε` means S' can match nothing — this handles the optional `else` clause.
- **Dangling else**: The grammar associates `else` with the nearest `if`, modelling real language behavior.
- **Recursive Descent**: Each grammar rule becomes a function; recursion handles nested structures naturally.
